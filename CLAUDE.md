# Claude Code Instructions for Orva

Read and obey the repository-root AGENTS.md before every task. It is the canonical engineering contract.

For non-trivial work also read:
1. PROMPT_MASTER.md
2. .agents/skills/orva-engineering/SKILL.md
3. docs/agents/CURRENT_STATE.md
4. docs/product/PRODUCT_VISION.md
5. docs/product/ROADMAP.md
6. The relevant docs/specs/ file

Inspect current Dart source, Drift schema/migrations, repositories, tests, and CI before making implementation claims. Do not trust stale status matrices.

Use the Orva engineering skill for feature work, reviews, architecture changes, schema migrations, Android widgets, calendar/time blocking, comparisons, missions, gamification, and analytics.

UI copy is pt-BR. Technical documentation and identifiers are English by default.

Identify acceptance criteria, source-of-truth records, migration impact, privacy risks, and test strategy before editing. Do not bundle unrelated roadmap items. Never overwrite user work or claim tests that were not run.

At handoff, report changed files, delivered behavior, exact tests/results, limitations, migration/backup impact, and the next task.
